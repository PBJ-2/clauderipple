## 함정 (이번 세션에서 실제로 겪음)
- **이 세션은 훅이 `youthful-grothendieck-496036` worktree에 묶인 것으로 본다.** 그래서 main 체크아웃과 직접 만든 worktree(`git worktree add`)에서는 Edit·Write가 막혔다(Bash 편집은 훅을 피하는 것이라 하지 않음). **워커는 Agent의 `isolation: "worktree"`로 띄워야 수정이 된다.** 결과 브랜치는 main 위에 cherry-pick이나 `--ff-only`로 합쳤다.
- `isolation: "worktree"`는 **메인 세션의 현재 셸 위치 저장소**에 worktree를 만든다. `cd apps/ripple-remote` 상태로 띄웠더니 앱 저장소에 만들어졌다. 띄우기 전에 저장소 루트로 돌아올 것.
- `git cherry-pick` 여러 개가 "local changes would be overwritten"으로 중간에 멈추는 일이 두 번 있었다(작업 트리는 깨끗). `git cherry-pick --quit` 후 남은 커밋만 다시 집으면 된다. `--abort`는 앞서 적용한 커밋까지 되돌린다.
- Windows CI에서만 깨지는 테스트 패턴 두 가지: 자식 프로세스 `import`에 `D:\…` 경로를 그대로 넣음(→ `file://` URL로), `app.js`를 CRLF 그대로 읽고 `"\n"` 경계를 찾음(→ `\r\n`을 `\n`으로 정규화).
- 릴리스 문서 4단계(격리 설치 확인)는 하네스가 `HOME` 설정 명령을 막아 이번에는 돌리지 못했다. 실설치 재시작과 응답으로 대신 확인했다.
- 모드 엔진 테스트 2건("automatic fable dispatches…", "a desktop survey draws over the band…")은 main에서도 실패한다. 이번 변경과 무관하며 아직 고치지 않았다.
